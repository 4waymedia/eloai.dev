Corpus Pipeline & Benchmarks

The dictionary is only as good as the corpus that built it. We need a data engineer who treats the pipeline as a first-class system — not scaffolding to be replaced later.

Full-time Remote Equity-included Early hire

The Pipeline

EloAI's dictionary is built from a corpus of YouTube ASR transcripts — 10 to 100GB of 30-second JSON chunks, deduplicated, cleaned, counted, and ranked. Every word and phrase in the corpus competes for an ID. The most frequent wins the shortest one. The pipeline that produces the corpus directly determines the quality of the dictionary.

Several components already exist: corpus_scanner.py handles ingestion and two-pass deduplication; word_frequency_counter.py counts surface forms; ngram_counter.py mines 2–9 word phrases; dictionary_builder.py assigns IDs and writes to LMDB. What's needed is someone to own the full system — extend it, harden it, instrument it, and make the benchmark results it produces trustworthy.

The acceptance criterion for the dictionary is quantitative: 99.25% corpus coverage, ~2x compression ratio (target 2.5x), 100% lossless round-trip. The gap between current and target is a data problem as much as a code problem.

What You'll Do

  • Own the full corpus pipeline from raw transcript JSON through to dictionary build — including ingestion, deduplication, normalization, frequency counting, n-gram extraction, and LMDB write
  • Close the compression ratio gap: current ~2x, target 2.5x — the primary lever is phrase-level n-gram coverage; diagnose what's being missed and fix it
  • Build out the benchmark suite: round-trip accuracy (must be 100%), compression ratio, token reduction, coverage by tier, OOV rate, lookup speed — reported per format and per corpus slice
  • Expand corpus sources beyond YouTube ASR: domain dictionaries (medical, military, psychology, science), structured text (Wikipedia, Common Crawl slices), and document formats (.log, .csv, .json)
  • Design the pipeline lab instrumentation — the internal review surface for corpus inspection, compression verification, EPA timeline visualization, stage distribution, and memory database auditing
  • Maintain the distinction between confirmed and projected metrics — measured results must never be conflated with targets in any output document, benchmark report, or dashboard

Who You Are

  • You've built data pipelines that had to be correct, not just fast. You know the difference between a pipeline that produces output and one whose output you can trust.
  • You instrument before you optimize. You measure where time and coverage are lost before you decide what to fix.
  • You treat benchmark methodology seriously. You know that a benchmark that can be gamed is worse than no benchmark, and you design tests that resist that.
  • You can read existing code before writing new code. Five components already exist. Understanding what they do before adding the sixth is how the system stays coherent.
  • You care about the distinction between "the corpus says this word exists" and "this word belongs in a production dictionary." Data quality is a judgment call, not just a filter threshold.

What This Isn't

This isn't a role managing ETL pipelines for a dashboard nobody reads. The corpus is the foundation that every other system depends on. Dictionary quality is directly downstream of pipeline quality. The benchmark numbers you produce are what the research claims rest on.

Compensation is competitive for an early data hire: base salary, meaningful equity, and direct influence over the data decisions that shape the system's performance claims. The pipeline is load-bearing.
