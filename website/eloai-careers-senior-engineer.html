The Work

EloAI is a semantic compression system built on a single insight: compression and meaning are the same operation. A 14MB LMDB dictionary encodes 83,000+ tokens — words, phrases, contractions — each one an ID that is simultaneously a compression address, a semantic coordinate, and a future LLM token.

We're at the inflection point. System 1 (lossless compression) is validated. System 2 (the cognitive architecture — perception, memory, emotion, reasoning, reflection) is in build. What's left is hard: C++ library for embedded hardware, an MCP server for IDE integration, a fine-tuning pipeline replacing BPE with our own dictionary, and a binary file format destined for IANA registration.

This is not an AI wrapper. We're rethinking tokenization from first principles — and we need an engineer who can hold a full architecture in their head, not just their ticket queue.

What You'll Do

  • Architect and deliver core subsystems: the libelo C++ public API (sc_encode, sc_decode, sc_open_library), the Python compressor pipeline, and the MCP server exposing semantic search to LLM agents
  • Build and validate the lossless encode/decode pipeline end-to-end — the acceptance criterion is decode(encode(text)) == text on every input, every time
  • Drive the fine-tuning experiment: replace Qwen3 3B's BPE tokenizer with the EloAI dictionary, initialize embeddings from FAISS domain vectors, and benchmark perplexity against baseline
  • Architect the embedded hardware integration — Arduino interaction loop + Whisper STT + 2GB on-device corpus — so the system can hold a conversation with no internet connection
  • Write the tests and benchmarks that prove coverage, compression ratio, round-trip accuracy, and lookup speed (target: ~5ns per ID in a packed binary in-memory array)
  • Review specs before writing code. Challenge assumptions. Tell me when something's wrong before we build it wrong.

Who You Are

  • You've shipped things at the systems level — binary formats, network protocols, storage engines, language runtimes. Not just features on top of frameworks.
  • You read specs before writing code. You know a wrong design decision costs ten times what a wrong line of code costs.
  • You're comfortable in C or C++ when the platform demands it. You don't need a managed runtime to feel safe.
  • You can hold an architecture in your head. EloAI has eight engines, two layers of encoding, five dictionary tiers, an embedded target, and an LLM fine-tuning experiment. Context-switching is the job.
  • You push back constructively. If the spec is wrong, say so before we build it. Silence that leads to rework isn't helpfulness.
  • You test your own assumptions. The acceptance criterion is a function call, not a demo. Round-trip accuracy is 100% or the work isn't done.
  • You're interested in what it means to compress meaning — not just bytes.

Background That Fits

None of these are requirements. All of them are relevant:

  • Experience with LLM tokenizers, vocabulary construction, or embedding models at the implementation level
  • Work on embedded or constrained systems — memory budgets, no-malloc constraints, C runtime environments
  • Background in linguistics, cognitive science, or affective computing (we're building a system that models emotional valence)
  • Military service or familiarity with controlled-vocabulary doctrine environments
  • Standards work — IANA, W3C, ISO, or similar. We're aiming for browser-native dictionary pre-installation, analogous to how TLS certs ship.

What This Isn't

EloAI is an early-stage research project with one founder. We're not a funded startup with HR, a roadmap deck, and quarterly OKRs. What we have is a validated system, a clear thesis, and a lot of hard build work ahead.

If you need a large team, established tooling, and a defined scope — this isn't the right fit. If you want to architect something genuinely novel while it's still small enough to understand completely, it might be exactly right.

Compensation is competitive for a seed-stage technical co-builder: base salary, meaningful equity, and a stake in the outcome. The right person for this role understands that the early build phase is where leverage lives.
