Product / UX Designer
Tools, Pipeline Lab & Public Surface

EloAI needs a designer who can make invisible systems visible — a cognitive architecture that runs in compressed binary deserves an interface that makes it legible without flattening it.

Full-time Remote Equity-included Early hire

The Design Problem

EloAI is a system that compresses meaning into 1-to-3 character IDs, stores them in a 14MB binary dictionary, and routes them through eight cognitive engines. None of that is visible by default. The pipeline lab — the internal tool for corpus inspection, compression verification, and memory database review — is where you first encounter what the system actually does.

The design challenge isn't making EloAI look impressive. It's making it legible: to researchers auditing the dictionary, to developers integrating the MCP server, to a non-technical audience reading the public site. Three very different surfaces. Three very different definitions of clarity.

The pipeline lab is the most important surface no one outside the project will see. The public site is the most important surface everyone will see first. Both need to be right, and neither exists yet in final form.

What You'll Design

  • Pipeline Lab: The internal review interface — corpus inspection, compression benchmarks, EPA timeline visualization, stage distribution, OOV word auditing, and memory database review. Power-user tooling that needs to communicate dense technical output without hiding it behind abstractions
  • eloai.dev: The public-facing website — research documentation, the MoL thesis, the .elo format spec, the careers page, and the project's identity. Audience ranges from LLM researchers to standards bodies to developers evaluating the MCP server
  • Elo Browser extension UI: The browser-native interface for the planned Elo Browser extension — compression status, dictionary coverage indicators, semantic layer toggles
  • MCP server developer experience: Documentation, onboarding flows, and API reference design for developers integrating EloAI tools into their IDE or agent environment
  • EloAI visual identity system: Formalize the design tokens already implicit in the project — the teal accent, monospace scaffolding, dark surface palette — into a composable system the team can use consistently

Who You Are

  • You design for systems, not screens. You understand that a data-heavy internal tool and a public research site share almost no UX assumptions, and you approach them differently.
  • You read technical specs before designing interfaces for them. You won't design an EPA timeline visualization without understanding what EPA is. You ask questions before you make assumptions.
  • You can produce and ship HTML and CSS when the situation calls for it — not as a secondary skill but as part of your normal workflow.
  • You have opinions about information density. You know that hiding complexity behind progressive disclosure is sometimes the right call and sometimes a failure of nerve. You can tell the difference.
  • You're drawn to tooling and developer-facing work — the kind of design that makes something hard to use become something you can't imagine not having.

What This Isn't

This isn't a role producing marketing graphics or polishing a product that already works. The design surface is largely undefined — which means you'll be establishing visual language, information architecture, and interaction patterns from scratch, in close collaboration with the engineer building the systems you're designing for.

Compensation is competitive for an early design hire: base salary, meaningful equity, and creative ownership of EloAI's entire visual and product surface — from the pipeline lab nobody will see to the public site everyone will judge the project by.
