Full-Stack Web Engineer
eloai.dev · Pipeline Lab · Browser Extension

EloAI's web surface is the system's public face and its internal instrument panel simultaneously. We need an engineer who builds both with equal care.

Full-time Remote Equity-included Early hire

Three Surfaces, One Engineer

EloAI has three distinct web targets that need to be built from the ground up. The public site (eloai.dev) communicates the research, the format spec, and the thesis to an audience of ML researchers, developers, and standards bodies. The pipeline lab is the internal review tool — corpus inspection, compression benchmarks, EPA timeline visualization, and memory database auditing for a technical audience that will not tolerate abstraction over detail. The Elo Browser extension is the browser-native interface for the EloAI compression layer, with dictionary pre-installation as the long-term target.

All three surfaces connect to the same backend: the EloAI semantic compression system, the LMDB dictionary, and eventually the MCP server. You're the engineer who makes the Python core accessible to web clients, browser contexts, and developer tooling.

What You'll Build

  • eloai.dev: Full site build on a modern stack — research documentation, MoL thesis presentation, .elo format spec, careers page, and the project's public identity. Content managed via Sanity CMS with schema models for dictionary entries, benchmark runs, and format token registry
  • Pipeline Lab: Internal web interface for corpus and dictionary auditing — compression stats, OOV word lists, EPA timeline charts, stage distribution histograms, coverage breakdowns by tier and format. Connects to the Python pipeline via an API layer you'll design
  • Elo Browser (Strategy A): Transpiler + service worker approach for browser-native dictionary integration — the first step toward making the EloAI dictionary a pre-installed browser primitive, analogous to how TLS certificates ship natively
  • MCP server web integration: The web-facing surface of the EloAI MCP server — exposing sc_encode, sc_decode, dictionary lookup, and corpus search to IDE agents and browser-based developer tools
  • API layer: Design and implement the interface between the Python compression core and all web clients — REST, WebSocket, or WASM bridge depending on what the latency target demands

Browser Extension Strategy

  • Strategy A (build now): Transpiler + service worker. EloAI dictionary runs client-side via WASM, intercepting fetch requests to compress/decompress content transparently. No browser modifications required.
  • Strategy B (future): CEF native shell for the EloAI IDE — a Chromium Embedded Framework build with the dictionary pre-installed natively.
  • Strategy C (long-term): Chromium fork with dictionary pre-installation at the browser level, analogous to how TLS root certificates ship. Browser-native semantic compression.
  • Your immediate target is Strategy A. You design it so that Strategy B and C are natural extensions, not rewrites.

Who You Are

  • You build web interfaces for technical audiences without dumbing them down. Developer tooling, internal dashboards, and data-heavy interfaces are where you do your best work.
  • You understand the browser as a platform — service workers, extension APIs, the fetch lifecycle, caching strategies. Not just React on top of it.
  • You can bridge Python and web. You've designed APIs that make a backend system usable from a browser client, and you know what belongs on each side of that boundary.
  • You're comfortable with data visualization at the level the pipeline lab requires — time series, distribution histograms, coverage breakdowns — not just charts from a library with default settings.
  • You find the idea of a browser dictionary pre-installation — making the EloAI semantic layer as ambient as HTTPS — genuinely interesting as a web standards problem.

What This Isn't

This isn't a role maintaining a marketing site or adding features to an existing product. The web surface is largely undefined — eloai.dev is live but sparse, the pipeline lab exists as a concept, and the browser extension is a documented strategy waiting for an engineer to execute it.

Compensation is competitive for an early web hire: base salary, meaningful equity, and ownership of the entire web architecture — from the Python-to-browser API contract to the browser extension strategy that could eventually make semantic compression a native browser primitive.
